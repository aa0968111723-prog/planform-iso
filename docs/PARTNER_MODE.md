# 夥伴模式（Partner Mode）— Visual-first Partner UX

## 目標

第一次看到系統的一般活動夥伴，**不需要教學**，要能在 10 秒內看懂四件事：

1. 場佈長什麼樣子
2. 自己站哪裡
3. 人從哪裡來
4. 下一步去哪裡

這一版沒有新增任何工程功能。Simulation、Asset Engine、Quick Agent、專業編輯模式
都沒有改變行為；夥伴模式是把同一份資料換一種說法。

## 這是一個獨立模式，不是換皮

進入夥伴模式後，編輯器的 chrome **整個消失**（不是被蓋住）：Topbar、左右面板、
底部工作流導覽、Selection Context Bar、AI sheet 全部 `display: none`，
換成兩條細長的橫向 strip：

```
┌──────────────────────────────────────────┐
│ 活動名稱            🟠 1 個地方要注意  離開 │  partnertop
│ 👀全部 👋報到組 💰收費組 🧭引導組 🧺生活組 │
├──────────────────────────────────────────┤
│                                          │
│              乾淨俯視 Canvas               │
│                                          │
├──────────────────────────────────────────┤
│ 📍 你在「報到區」 ⬅️ 人從「引導」來   看步驟 ▸│  partnerdock
│ ▶ 演練一次   ✦ 更順的排法   🖼 存成圖      │
└──────────────────────────────────────────┘
```

- **任何寬度都沒有固定 Sidebar** —— 手機、平板、桌機共用同一個 canvas-first shell。
  瀏覽器測試直接斷言 `baseRect.width === canvas.width`（chrome 只吃上下，不吃左右）
  以及 Canvas 佔比 ≥ 70%。
- **唯讀**：夥伴點畫面不會選取、不會拖動物件，鍵盤只剩 Esc（收 sheet → 離開）。
  相機的平移縮放照常。
- 尺寸 / X / Z / 吸附 / Inspector / 進階參數在夥伴模式**不存在**，不是折疊起來。

## 五種角色視角

`src/core/partner.ts` 是唯一的規則來源（純函式、可單元測試）：

| 角色 | 強調的區域 | 強調的動線 | 強調的物件 |
| --- | --- | --- | --- |
| 全部 | 全部 | 全部 | 全部 |
| 報到組 | 報到區 | 入場、報到 | serviceRole=checkin |
| 收費組 | 報到區 | 報到 | serviceRole=payment |
| 引導組 | 鞋子、背包、小組 | 入場、鞋子、背包、入座、小組 | 門、投影幕、guidance |
| 生活組 | 生活組、講師禪定 | 工作人員、小組 | 桌椅、地墊、storage |

選了角色之後，不屬於他的區域淡出、動線變灰、物件隱藏，只留下「你的位置、你的動線、
你的工作區、下一站」。有明確 `serviceRole` 的物件**只**用角色判斷 —— 報到桌和收費桌
都是 `regTable`，若退回用 kind 比對，兩組會互相搶到對方的桌子。

## 場上的視覺語言

- **區域**：大型圖示＋中文名稱（高解析度 sprite，非放大的小字），自己的區域填色較實、
  其他區域淡到剩輪廓。
- **動線**：粗箭頭＋方向＋①②③ 步驟徽章。在「全部」總覽不顯示動線名稱 —— 箭頭、顏色
  與編號已經說完流程，四條路名反而讓手機畫面變成標籤湯；選角色後名稱才回來。
- **問題**：直接標在場上，🔴 紅／🟠 橘／🟢 綠。畫面上最多 3 個，**只有紅、橘會帶文字**
  （短標題），綠色只是安心的點；完整的「該怎麼做」在點燈號後的「要注意的地方」清單裡。

## 活動演練 Timeline

`src/core/rehearsal.ts` 把既有 DES 結果翻成生活化句子：

```
17:20 🚶 夥伴開始進場
17:23 ⏳ 報到開始排隊
17:24 ⚠️ 報到開始塞車，6 個人在等
18:03 ✅ 報到恢復順暢
18:06 🎉 全部就位，活動可以開始
```

規則：每個站點最多三拍（開始排隊 / 塞車 / 恢復），加上開場與結束。事件數是**硬上限**，
問題優先佔位 —— 一份掃不完的清單跟沒有清單一樣沒用。

## AI 優化 = 視覺 before / after

「✦ 更順的排法」呼叫既有 Quick Agent（清門前淨空 ＋ 報到收費分流），拿到 draft 之後：

- 左右並排兩張乾淨平面圖：**現在的排法** vs **建議的排法**
- 四列人話數字：最多幾個人在排隊 / 平均要等多久 / 最久要等多久 / 多久全部就位
- 一句結論：「建議方案比較順：排隊少 5 人、平均少等 2 分。」或「兩個方案差不多，
  保持目前的就好。」
- 決定按鈕釘在捲動區外面，永遠一鍵可及：用建議的排法 / 保持現在的

沒有 utilization、throughput、bottleneck station id 這類字眼。若 agent 交回來的方案
和現況完全一樣，直接說「目前的排法已經夠順」，不會端出一組沒有差別的對照圖。

## 驗收

- `test/partner.test.ts`：角色 focus / emphasis、briefing 文案（含「不得出現工程用語」
  的正規表達式斷言）、marks 排序與上限、時鐘與時長格式、Timeline 敘事、before/after
  比較的三種結論。
- `e2e/partner.spec.ts`（`npm run test:e2e`）：在 390×844、360×800、768×1024、
  1024×768、1366×1024 逐一驗證 canvas-first 無 sidebar、五個角色、演練時間軸、
  before/after 圖與數字、唯讀、離開後編輯器完好、專案資料未被修改。

## 與舊「檢視給團隊」的關係

夥伴模式取代了原本的 teamView overlay。舊版只是把 chrome 藏起來、加一條標題列與圖例；
新版是完整的角色視角 + 演練 + before/after，並且保留原本能做的事（名稱、說明、
存成分享圖）。編輯器的入口按鈕改為「👥 夥伴模式」，compact 版本在 More sheet 裡。
