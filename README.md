# PLANFORM｜活動空間彩排

> **先排好，再上場。**
>
> 活動開始前，把場地、3D 道具、人流與互動先排好、先彩排，
> 再把清楚的場刊圖交給夥伴。

可安裝的手機／平板／桌面 PWA（不上架商店）。為淡江大學教室、
禪學社社課／茶會／演講／新生活動的真實現場而做：報到、收費、引導、
鞋子、背包、入座、地墊與工作人員配置。

**Preset-first, fully customizable** — 預設非常方便，但一切仍可自訂。

## 一般使用（不用懂 CAD / 3D / 工程參數）

1. **我的專案**：開 app 先看到自己的活動列表 →「＋ 建立新專案」
   （一場活動一份專案；建立新的永遠不會蓋掉舊的）
2. **快速開始**：今天要排什麼？→ 選「淡江教室模板」／我的場地模板／空白場地
3. 勾需求（地墊、報到、收費、鞋子區、背包區…）＋ 輸入人數 → **建立場佈**
4. 直接在畫布上拖曳調整；「排地墊」選 20/30/40/60 人一鍵出 A/B/C 方案
5. 畫動線：選 入場/報到/收費/鞋子/背包/入座 → 在畫布上點一點 → 完成
6. **分享**：場佈總覽圖 / 動線圖 / 地墊座位圖 / 工作分區圖 / 物資清單圖 /
   夥伴觀看圖 — 手機直接開分享傳 LINE
7. **夥伴模式**：給夥伴的唯讀視圖（全部/報到組/收費組/引導組/生活組），
   10 秒看懂自己站哪、人從哪來、下一步去哪，一鍵存成圖

## 功能總覽

- 淡江教室 / 一般矩形 / 空白 場地模板 ＋「儲存為我的場地」
- 教室／走廊真實尺寸（1 單位 = 1 公尺）、地磚吸附、現場校正
- 常用物資庫（地墊/桌椅/報到桌/收費桌/投影幕/鞋架/指示牌…）＋
  我的素材（拍照建立 proxy、匯入 GLB/GLTF）
- 區域（報到/收費/鞋子/背包/生活組/講師/小組/自訂）：點畫面放置
- 排地墊：人數 → A 整齊排列 / B 中央走道 / C 較寬鬆，看圖套用
- 動線：畫布點選節點、粗箭頭、①②③、起點/終點
- **活動流程模擬（本地 DES，不需網路/AI）**：人數/現場繳費/人力/到齊時間 →
  最多排隊、平均等待、最塞的站、全部完成時間 → ✦ 幫我改善
- ✦ AI 幫我：用一句話說需求 → 產生 A/B/C 三個排法 → 比較 → 選一個 → 預覽 →
  套用。一律先預覽再套用，沒有雲端金鑰也全部可用（見下方「AI 幫我」）
- 檢查中心：超界/重疊/擋門/走道過窄/視線 等規則（門檻在進階可調）
- 三段 Responsive Workspace（手機 ≤600 / 平板 601–1199 / 桌機 ≥1200），
  Canvas-first、單列 Header、Bottom Sheet
- **我的專案**：一場活動一份專案，各自獨立自動儲存；重新命名／複製／刪除
  （刪除有 4 秒復原）；一份壞掉不會影響其他份，原始資料可下載
- 同一個專案裡可以存多版「場佈」（不同排法）；場地模板另外存
- 本機自動儲存（含損壞自動備援）、JSON 匯入匯出（匯入＝建立新專案）
- PWA：離線可用、有新版本時提示更新、「更多 → 關於」可看版本/commit/建置時間，
  部署後 `/version.json` 可查線上版本

## ✦ AI 幫我：一句話 → 三個排法 → 比較 → 套用

輸入一句話，例如：

> 幫我排一個 60 人的禪學社茶會，入口先報到，收費另外分流，
> 地墊放中央，門口保留 1.2 公尺，最後模擬人流。

會得到：

1. **它理解成什麼**——人數 60（讀自「60 人」）、活動類型茶會、
   門前保留 1.2 公尺、目標「分流」與「不擋門」。看得到才能糾正。
2. **它假設了什麼**——沒說的部分（工作人員人數）會明說用了什麼預設值。
3. **三個排法**，每一個都用**跟手動編輯同一套**驗證器與模擬器量過：
   可坐幾人、平均等多久、最久多久、最塞在哪、幾個問題、幾分。
4. **推薦哪一個，以及為什麼**。違反你明講要求的方案會被標示原因並排除在
   推薦之外，但仍然列出來讓你自己看。
5. **預覽**在 3D 畫布上，按「套用」之前正式專案完全不動；套用是一步，
   可以 Undo。

分工是刻意的：**AI 只負責理解你的意思與選擇目標；座標、碰撞、走道、
距離、容量與模擬全部由程式計算。** 方案分數高是因為配置好，不是因為
引擎拿自己的尺量自己。

也支援直接操作：

- 「把報到桌移到入口右側，收費桌移到左側，兩邊各保留一公尺走道」
- 「找出目前最塞的地方，提出兩種改善方案」
- 「建立簡化 3D 素材，尺寸先用 180×60×74 公分，放到報到區」
- 「產生一張工作人員看得懂的場佈圖與物資清單」

場上找不到的東西不會被亂猜——它會說「場上找不到報到桌，沒有移動任何東西」。

### 不用雲端 AI

出貨的 provider 是本機的結構化解析器：**沒有網路、沒有金鑰、
結果每次都一樣**。`AgentProvider` 抽象保留，之後可以換成雲端 LLM；
換了之後工具層、預覽與套用的閘門完全不變，而且雲端 provider
**不會拿到整份計畫**——把句子變成座標的那一步在本機完成。

沒有設定任何 provider 時，場佈、驗證、模擬與手動操作完全可用。

### 設計知識與資料來源

`src/core/spatialKnowledge.ts` 有 25 條可引用的設計依據，每一條都帶
`sourceUrl` / `sourceType` / `retrievedAt` / `confidence` / `limitations`。
研究過程與 310 個來源在 [docs/research/spatial-design/](docs/research/spatial-design/)。

涉及消防、無障礙、避難或法律的條目一律標記需要人工確認，只顯示：

> 設計提醒，仍需依現場與專業規範確認。

程式層面禁止出現「已符合所有法規」「已通過安全檢查」「一定可以使用」，
並由測試對整張知識表強制檢查。**本工具不做容留人數計算、避難寬度計算，
也不做無障礙認證。**

## 擺攤小物、文宣與背景圖

道具工作室除了互動道具（骰子、轉盤、抽卡箱），還內建擺攤實際會用到的東西：

| 類別 | 內容 |
|---|---|
| **文宣** | X 展架、易拉寶、A1/A2 海報、珍珠板立牌、桌上立牌 A5、桌前布條、直式布條 |
| **背景** | 240×240 與 300×250 合照背景牆（桁架＋布幔，含合照站位） |
| **擺攤小物** | DM 架、名片架、抽獎箱、募款箱、試吃盤、QR 立架、集章台、獎品陳列架、桌巾 |

用一句話就能做：

> 幫我做一張 A2 海報，印上「淡江禪學社招生」
> 做 500 張雙面 A5 傳單
> 做一個 X 展架，寫「領袖禪訓營」
> 做一個合照背景牆

### 背景圖與文宣可以貼上真的圖

匯入照片之後，可以把它貼到背景牆、海報或展架的印刷面上：

> 把剛剛匯入的那張圖貼到背景牆上

沒有貼圖之前，面板會顯示文字（例如「背景主視覺」），
方便先確認尺寸與位置；貼上之後就是真的圖。
讀不到圖時保留文字，而不是讓背景牆消失。

### 印刷品同時知道「多大」與「怎麼印」

一張海報如果只是一片白色平面，它能告訴你它站在哪，卻答不出社團真正要問的
問題——**要印幾張、什麼尺寸、什麼材質、完稿檔多大**。

所以印刷品同時帶兩組尺寸：

- **公尺**給版面與碰撞檢查
- **公釐**給印刷廠（台灣印刷廠都報公釐，ISO 216 也以公釐定義）

兩者單向推導，不可能發生「版面上 60 公分、訂單上 A3」。

尺寸來源分兩種，程式裡明確標示：

- **ISO 216 A 系列**是定義值（A5 = 148 × 210 mm）→ `authority: "iso"`
- **X 展架 60×160、易拉寶 80×200** 是市售產品尺寸，不是任何標準組織訂的
  → `authority: "market"`

「分享 → 物資清單」會另外列出**可直接送印的清單**，含完稿尺寸（含出血）：

```
招生傳單   A5（148 × 210 mm）· 直式 · 銅版紙 · 雙面 · 500 份 · 出血 3 mm
           完稿 154 × 216 mm
X 展架     X 展架（600 × 1600 mm）· 直式 · PP 合成紙 · 單面 · 2 份
           完稿 600 × 1600 mm
```

只算**實際放進場的**——設計了一張沒放進去不算訂單。物資與文宣分開列，
因為那是兩件不同的差事、不同的死線。

## 本機開發

需要 Node.js 22+。

```bash
npm install
npm run dev       # 開發伺服器 http://localhost:5173
npm run build     # 產生正式版（含 PWA service worker 與 version.json）
npm run preview   # 預覽正式版
npm run test      # 單元測試（Vitest）
npm run test:e2e  # 瀏覽器測試（Playwright，含 10 viewport + Golden Flows）
npm run lint      # ESLint
npm run typecheck # TypeScript 型別檢查
npm run verify    # lint + typecheck + test + build 一次跑完
```

## 部署

`main` 推送後由 GitHub Actions 建置並發佈到 GitHub Pages
（`.github/workflows/deploy.yml`；相對路徑 base，子路徑可直接運作）。
也可將 `dist/` 部署到任何靜態主機（Zeabur 等）。

## 安裝到手機（不上商店）

1. 用手機瀏覽器開啟本站網址（需 HTTPS）
2. **Android Chrome**：選單 →「安裝應用程式」或「加到主畫面」
3. **iPhone Safari**：分享 →「加入主畫面」
